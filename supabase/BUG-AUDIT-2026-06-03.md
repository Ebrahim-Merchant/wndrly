# Wndrly Bug Audit — 2026-06-03

## Bugs Found & Fixed

### 🔴 CRITICAL: audit_log sequence out of sync
**Symptom:** `duplicate key value violates unique constraint "audit_log_pkey"` on every login  
**Root cause:** All PostgreSQL sequences were out of sync with actual data (rows inserted with explicit IDs during migration bypassed sequences)  
**Fix:** Ran `setval()` on ALL table sequences to `MAX(id)` via a PL/pgSQL DO block  
**Affected tables:** audit_log, users, settings, trips, days, places, reservations, budget_items, notifications, and ~50 others  

### 🔴 CRITICAL: INSERT OR IGNORE / INSERT OR REPLACE not converted for PostgreSQL
**Symptom:** Silent failures on any write to tables using SQLite-specific upsert syntax  
**Root cause:** `pg-adapter.ts` `convertQuery()` didn't handle `INSERT OR IGNORE`/`INSERT OR REPLACE`  
**Fix:** Added conversion logic to `convertQuery()`:
- `INSERT OR IGNORE INTO` → `INSERT INTO ... ON CONFLICT DO NOTHING`
- `INSERT OR REPLACE INTO` → `INSERT INTO ... ON CONFLICT (first_col) DO UPDATE SET ...`

### 🔴 CRITICAL: Composite-PK tables with INSERT OR REPLACE broken
**Symptom:** Wrong conflict target → PostgreSQL error on upsert  
**Root cause:** pg-adapter heuristic (first column = PK) fails for composite PKs  
**Fix:** Replaced `INSERT OR REPLACE` with explicit `ON CONFLICT` in:
- `notificationPreferencesService.ts` → `ON CONFLICT (user_id, event_type, channel)`
- `journeyService.ts` → `ON CONFLICT (journey_id, user_id)`
- `oauthService.ts` → `ON CONFLICT (client_id, user_id)`
- `reservationService.ts` → `ON CONFLICT (reservation_id, day_id)`
- `mapsService.ts` → `ON CONFLICT (place_id, lang, expanded)`

### 🟡 MINOR: Tables without `id` column cause error on INSERT RETURNING id
**Symptom:** `column "id" does not exist` error for tables like `app_settings`, `place_tags`, composite-PK tables  
**Fix:** Added try/catch in `Statement.run()` — if `RETURNING id` fails on a no-id table, retries without RETURNING

## Recommendations

1. **Connection pooling**: Workers use their own pools (max 5 each, 10 workers = up to 50 PG connections). Supabase free tier has a 60-connection limit — monitor usage.
2. **Sequence health check**: Add a startup check that verifies sequences are in sync (e.g., compare `last_value` of sequence against `MAX(id)` of table).
3. **pg-adapter unit tests**: Add tests for `convertQuery()` covering INSERT OR IGNORE, INSERT OR REPLACE, named params, and SQLite function substitutions.
4. **Transaction support**: Current `transaction()` wrapper is a no-op (each statement gets its own connection). Multi-statement operations are not truly atomic. Low risk for current codebase but worth noting.
